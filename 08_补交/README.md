## 2. 本地与线上不同运行分别计分 → 表1

两套运行是**不同的实现**，不能只报一个数：

| 运行 | 实现 | 得分 |
|---|---|---|
| 本地运行 | Python：bge-small-zh 神经 embedding + BM25 混合检索，top-8 | 严格 **9/15**（宽口径 10/15，Q9 属碰巧命中不计） |
| 线上运行 | 浏览器：纯 BM25 静态索引，自适应策略 auto | **9/15** |

**两个 9 不是同一批题**，差异 3 道：

- **Q1**（茅台营收）：本地 ✓ / 线上 ✗ —— 线上没有神经向量，数字型表格块字面重合度低，抓不住；
- **Q10**（茅台 vs 五粮液毛利率）：本地 ✗ / 线上 ✓ —— 线上按公司分层召回补回了覆盖垄断；
- **Q9**（哪家毛利率最高）：本地 △（碰巧命中，严格口径不计）/ 线上 ✗。

⇒ 结论不变但更清楚了：**神经 embedding 救单公司事实题，分层召回救跨公司题**，两者不能互相替代。

## 3. 召回与答案表现分别评价 → 表2

两层不是一回事，分三个口径报：

| 口径 | 非全景题（12 道） | 全景题（3 道） | 含义 |
|---|---:|---:|---|
| 召回层（证据块进没进 top-8） | 9/12 | 0/3 | 标准答案需要的那一块有没有被送进来 |
| 首要数字（答案能不能成立） | 11/12（Q14 是文字型答案，按措辞核对判 △） | 3/3 | 标准答案里最主体的那个数，有没有出现在召回原文里 |
| 全部数字齐全（满分答案） | 6/12 | 0/3 | 标准答案里每个数字都能在召回原文里找到，**且涉及的每家都有数** |

全景题三个数字要合着看：首要数字都命中了（比如 Q7 的 7.52% 确实在 top-8 里），
但**涉及的 15 家里只有 2–4 家有数**，所以答案层照样是 0/3 齐全 ⇒ 这正是全景题必错的原因。

判定是机械的：抽出标准答案里的关键数字，去 top-1…top-8 的原文逐块找，记首次命中的位次，
再统计命中的公司数。匹配时容忍**亿元 / 万元 / 元**三种写法（按 1、1e4、1e8 三个量级做 0.5% 相对误差匹配），
避免"单位不同"被误判成没答对。

**典型差异**：Q7/Q9/Q10/Q12 召回层是 ✗，答案层却显示"数字出现过"——
因为那个数恰好躺在 top-1 里，但**只有 1 家公司有数、其余 14 家根本没进上下文**，答案照样不成立。

`05_评估/查证_标准答案.py` 人工回原文核过的结果。

## 6. 系统实际回答 与 逐题判定 → 表5（这一条此前是空的）

批改指出的问题成立。这里分两层答复，别混在一起：

**（a）线上页面的答案区不会空**——`05_评估/验证_线上回答非空.js` 不启浏览器，
直接加载线上同一份 `assets/`（index.bin.gz / meta.json / config.json / dict.txt.gz / text/ 分片）
和线上同一个 `assets/retriever.js`，逐字复用页面 `app.js` 里的 `answerExtractive`，
把这 15 题跑了一遍：**15/15 答案区全部非空**（最短 315 字、最长 1,100 字），
全景题在页面默认自适应策略下覆盖 15/15 家。

**（b）但提交材料里确实没存回答文本**——上一版只落了「检索命中 / 排名 / 证据摘录」，
没有把系统生成的回答本身存下来，所以看不到答案、也就谈不上答案正确性评价。表5/表6 补的就是这一层。

**回答怎么来的（抽取式，不调用任何付费模型）**：`05_评估/生成_实际回答.py` 按写死的确定性规则，
从 top-8 原文里抽——科目关键词 → 关键词之后的第一个合格数字 → 按类型归一单位
（金额 / 比率 / 计数 / 文字）→ 组装成一句中文回答 → 附「公司＋年报页码」出处。无随机、无网络。

15 题逐题给出：**系统实际回答 / 标准答案 / 判定 / 证据理由 / top-8 召回块**。
判定汇总：

| 判定 | 题数 | 说明 |
|---|---:|---|
| 正确 | **8/15** | 点名公司对，且关键数值或措辞全对 |
| 部分 | **4/15** | 公司对但数值缺或错；或只比较到部分公司（Q8/Q10/Q11/Q12） |
| 错误 | **3/15** | Q4 抽到上一年度分红方案、Q7 点名错、Q14 没给出意见类型 |

判定口径写死在脚本里：正确＝点名公司对 + 关键数值/措辞全对；部分＝公司对但数值缺或错、
或数值对但公司错/不全、或全景题只覆盖到部分答案公司；错误＝公司错且值错或压根没抽出数值。

三道典型翻车，理由都是可逐行核对的：

- **Q7（营收增速最快）**：top-8 只覆盖 6/15 家，答案公司山西汾酒**根本没进上下文**，
  系统只能在被召回的 6 家里取极值 → 答"金徽酒 -3.40%"（因为其余更负）⇒ 判**错误**；
- **Q4（2025 年度分红）**：抽到的是 **P34「2024 年年度利润分配」276.24 元**，问的是 2025 年度
  （279.93 元）⇒ 检索没区分报告期，判**错误**；
- **Q14（审计意见）**：top-8 命中的是审计报告的开头段（"一、审计意见 我们审计了…"），
  没有"无保留意见"这一措辞 ⇒ 判**错误**（与表2 的发现一致：P35 是内控审计意见，财报意见在 P2）。
