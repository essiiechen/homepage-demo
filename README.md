# 白酒上市公司年报问答知识库（2025 年报 · 检索增强问答）

《学会使用大模型》第三周作业 · 方向 A。同一批财报做一套"能提问、答案带出处"的问答系统，
然后用 10 道题回答作业的核心问题：**什么问题该建库，什么问题该微调。**

## 一句话结论

**单公司事实题（要某个具体数字）检索 7/7 全部命中；跨公司全景题（"15 家里谁最…"）top-8 检索下
gold 块 0/3 召回——根因是 top-k 语义截断最多覆盖 8 家公司，结构上不可能召回全（10 题检索可答 8/10，
Q9 碰巧答对是因为正确公司恰好挤进了前 8）。只换召回策略（分层召回，每家公司各取 2 块）不改任何模型
参数，就修到 3/3 召回。要稳定口径/叙述方式才轮到微调；跨实体聚合的正解是先 ETL 成结构化表，
建库和微调都不对。本次评估的判定全部基于检索（gold 块是否进 top-8），不依赖任何大模型。**

## 快速开始

```bash
pip install -r requirements.txt

# 1. 下载年报（可重复跑，已有 sha1 会跳过）
python 01_下载/下载_财报.py

# 2. 解析：文字 + 表格按行列还原 + 页码
python 02_解析/解析_财报.py

# 3. 切块 + 建索引（BM25 + bge-small-zh 向量，自动下载模型；无网可退 TF-IDF）
python 03_索引/切块.py
python 03_索引/构建_索引.py --backend sbert --tag bge   # 或 --backend tfidf --tag tfidf

# 4. 问答页面
python 04_问答/app.py            # http://127.0.0.1:8791

# 5. 评估（10 题逐题记录 + 召回策略对照实验）
python 05_评估/评估_10题.py
python 05_评估/对比_跨公司召回策略.py

# 6. 一页结论 PDF
python 06_结论/生成_一页结论.py
```

大模型答案可选：把 OpenRouter key 放进 `.env`（参考 `.env.example`），不配置则自动降级为
纯检索模式。key 不会进仓库（`.gitignore` 已含 `.env`）。

## 评估结果摘要

| 题型 | 题数 | gold 块召回 | 说明 |
|---|--:|--:|---|
| 单公司事实题（数字/比率/分红/渠道/员工） | 7 | 7/7 | 含答案的表格块全部进 top-8（最好第 1 位），出处正确到页码 |
| 跨公司全景题（谁最快/谁亏损/谁最高） | 3 | 0/3 | top-8 只覆盖 5/15 家，正确答案所在块未进候选 |

召回策略对照（同一模型、同一数据，只改召回）：

| 策略 | 覆盖公司 | Q7 增速最快 | Q8 谁亏损 | Q9 毛利率最高 |
|---|--:|---|---|---|
| A 全局 top-8 | 5/15 | ✗ | ✗ | ✓（运气好） |
| B 全局 top-40 | 12–14/15 | ✗ | △ 找到主要答案 | ✓ |
| C 分层（15 家×2） | 15/15 | ✓ | ✓ | ✓ |

逐题的召回块、答案、判定与"错在哪"见 `05_评估/逐题记录.csv`（同目录 .md 版可读性更好）。

## 结论：同一批财报，什么该建库、什么该微调

1. **建库（检索）**：点名了公司、要某个具体数字或事实的问题。答案是原文里的一行，
   检索能精确命中且可给出处；年报年年换，库可以增量重建。
2. **微调**：要稳定的口径、术语、组织答案方式的问题（"用董秘的语气解释为什么下滑"）。
   这是检索给不了的——检索只能抄原文，学不会"先行业、再公司、后措施"的叙述结构。
3. **两个都不对**：跨全部实体聚合、排序、比较。top-k 语义截断做不了全集扫描，
   微调更不该用来记数字。正解是把关键指标 ETL 成结构化宽表再读表。

一个诚实的注脚：第一版标准答案我自己就错了一题（Q8 漏了亏得更多的顺鑫农业），
是回原文核对才发现的——这反过来印证：人对数字的记忆不可靠，检索到的原文才可靠。
评估口径注脚：本次 10 题的判定全部基于检索（gold 块是否被召回进 top-8、召回块是什么、错在哪），
不依赖大模型；页面里的 LLM 答案生成只是可选增强，无 key 自动降级为纯检索模式。
